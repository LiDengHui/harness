---
id: code-review
name: 代码评审
description: 对一段已有改动做评审，只报告证据支持的发现，不改代码。
when: 用户提供或指向一段已经存在的 diff、分支或提交并要求评审；不是要求实现，也不是要求修复。
stages:
  - id: establish-base
    objective: 先确定评审的固定点，也就是基线提交或拿到的 diff 本身，并确认改动范围。
    agent: code-reviewer
  - id: review
    objective: 只读改动本身以及依赖它的调用方，按读者会遇到的顺序给出发现，每条附文件、行、后果和最小修复。
    agent: code-reviewer
    depends_on:
      - establish-base
    verify:
      - ["cargo", "test"]
---

评审的是改动，不是整个仓库。固定点没定下来之前，任何发现都可能是对旧代码的误判。

每条发现都要能回答：文件在哪一行、什么坏了、最小修复是什么，以及你是读出来的还是跑出来的。没跑过的测试只能算怀疑，要明说是怀疑。

优先看后几类，回归通常藏在里面：错误路径是否被正确处理、是否有别的调用方依赖旧行为、新行为是否有会在回退时失败的测试、路径与单位与生命周期是否和仓库其余部分一致。
